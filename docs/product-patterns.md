# Collaboration features adapted for MyFTCSpace

The project lead requested useful features inspired by Slack, Axero, monday AI Work Platform, Zoho WorkDrive, ScreenConnect and EverLeagues. This implementation adapts workflow patterns to FTC teamwork and the existing privacy/mentor-review model. It does not copy product branding, ratings or proprietary source code, and it does not claim an integration or equivalent feature coverage.

## Selected patterns and working implementation

| Reference | Pattern selected | MyFTCSpace implementation |
| --- | --- | --- |
| [Slack channels and canvases](https://slack.com/help/articles/1500000019361-Keep-work-organized-with-channels) | Work organized around a topic with its discussion and regular references nearby | **Team hub → Conversations** groups existing tasks by work area. Search includes task descriptions and replies. Each task has a persistent discussion using its existing comments; a reply draft stays attached to the correct task. **Team brief** puts team purpose, next meeting agenda, coach guidance and decisions together. |
| [Axero knowledge spaces](https://axerosolutions.com/platform/workspaces/) and [knowledge base](https://axerosolutions.com/platform/knowledge-base/) | Organized spaces, searchable guidance, content ownership and visible permissions | **Robot & resources → Knowledge spaces** groups accessible resources by category, with owner/source search, sorting and links into the existing editor. Hidden documents do not contribute names, spaces or counts for students. |
| [monday project management](https://support.monday.com/hc/en-us/articles/360014437599-Project-management-with-monday-com) | Owner workloads, clear statuses, dependencies and a view of the next deadlines | **Tasks → Plan** uses actual assignments and due dates to show owner workloads and mutually exclusive overdue/blocked/upcoming/undated groups, with existing editor and focus-session shortcuts. Existing Board/List filters and dependency checks remain active. Counts are task counts, not measured capacity or available hours. |
| [Zoho WorkDrive team folders and permissions](https://help.zoho.com/portal/en/kb/workdrive/frequently-asked-questions-faqs/team-folders/articles/team-folders-faqs) and [version/control overview](https://www.zoho.com/workplace/help/getting-started-with-zoho-workdrive.html) | Organized documents, deliberate access and review of current content | Resource spaces show owner, reviewed date, source/provider and audience. **Needs review / Reviewed** filters and the next-item review action make stale or unapproved guidance actionable. Existing shared revisions and private evidence attachment/consent controls remain the persistence/recovery mechanism; this adds no third-party drive or document co-editing. |
| [ScreenConnect support tools](https://www.screenconnect.com/products/remote-support-software) | Guided troubleshooting and useful diagnostics for support | **Team hub → Help desk** provides a step-by-step flow for sync, invitations, uploads and permissions; an explicit read-only sign-in/membership check; browser connection status; and a fixed-label, sanitized summary the visitor can copy and review. Coach/mentor escalation, routine lead support and privacy-maintenance links are visible. No screen capture, remote control, session recording or device-agent installation is introduced. |
| [EverLeagues team workspace](https://www.everleagues.com/features-benefits/) | A single team place connecting communication, tasks, information and organization roles | The **Team hub** joins task conversations, team updates/decisions, next-event context, resource shortcuts, actual activity and guided help, within the existing team/account/role boundaries. Activity uses posted updates and task replies; it does not invent read receipts, presence or completed-work timestamps. |

Primary product documentation was consulted for pattern selection. These are design adaptations, not a claim that a particular feature is objectively the best or available in every vendor plan. The pasted comparison scores were not used as verified ratings.

## Data access and review boundaries

This feature pass adds no stored personal-data field, collection, storage provider, integration or dependency. It uses existing tasks/comments, announcements, resources, robot guidance, schedule and session membership. Reply/update visibility is disclosed before submission; the coach/mentor reporting route remains available. A task workstream is an organizational filter within a team, not a separate private access boundary.

New comment and announcement entry points use the existing mutation and server authorization policies. Drafts are reset on account/team/season/role changes; retained old submit callbacks carry the original scope so they cannot post into a new workspace. Concurrent task comments and teammate field edits are preserved. All new search and counts operate on role-visible records, and document-space metadata is filtered before presentation.

The visited Team hub stays in a hidden, scope-bound React surface when navigating to another section, so unposted reply/update drafts remain in tab memory when opening a task or meeting. Its update dialog closes on navigation; the text is retained. Browser/tab close with unposted drafts triggers the browser's standard leave warning. No draft content is written to localStorage for shared workspaces. Global search now matches stored task-reply and resource-note text and opens an exact team announcement in the brief.

The help check performs a visitor-triggered GET to the existing session endpoint and never retries writes. The support summary is constructed from an allowlist of generic states and excludes account IDs, team names, task/file text, raw error messages, invitation codes and tokens. Copying the summary is local; sending it remains a visitor action through the school's approved channel.

The existing release fingerprint changes with this source, so an approval for the earlier build cannot silently authorize it. The original readiness checklist still requires the responsible adults to review the exact release, moderation coverage and actual vendor/organization terms. New AI processing, public chat/profiles, remote device access, automated messages and external services would need their own implementation and review; none is represented as present by these adaptations.

## Validation

Focused tests exercise actual task-planning/editor/focus interactions, resource-space permissions/review actions, task-reply drafts and concurrent edits, announcement persistence, support diagnostics and sensitive-data exclusion. Accessibility checks cover the new controls and views, including task conversations, update dialog and guided support.

Automated semantics are not a manual device, contrast or screen-reader certification. The full release checklist and external approvals remain recorded in [the release evidence packet](release-evidence.md).
